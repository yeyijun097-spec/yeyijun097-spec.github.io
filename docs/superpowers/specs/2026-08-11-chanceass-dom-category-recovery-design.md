# chanceAss DOM 所属品类与聊天页恢复修复设计

## 目标

修复线上识别流程中两条独立故障链：

1. 已选中正式营订单后，详情页中明确标记为“所属品类”的文本未写入 S 列。
2. 聊天右侧上下文读取超时后，页面恢复失败，导致该行不生成三天总结和风险判断。

## 范围与边界

- S 仅接受订单详情中字段标签明确为“所属品类”“课程品类”或“品类名称”的文本值。
- 详情根仍必须与当前选中订单的主订单 ID 精确一致；不得把订单列表、机会列表或其他订单的品类写入 S。
- Q 保持由订单购买类型判断，R 保持现有训练营名称/订单商品名称规则。
- 不改变真实后台表单的写入行为；本修复只读取页面 DOM 并写入识别结果文件。

## 方案

### S 列详情读取

点击“查看详情”后，在有限时段内轮询详情 DOM，直到同时满足：

- 当前详情存在与选中订单 ID 精确匹配的字段；
- 该详情的商品信息区域或其关联内容出现允许的品类标签；
- 标签对应唯一的非空文本值。

读取器兼容以下页面结构：标签和值分别位于相邻节点、同一字段项中的子节点、同一行的内联文本，以及折叠/滚动区域在展开后出现的文本。若候选详情根不唯一、订单 ID 不匹配、品类值冲突或没有明确标签，则 S 保持为空。

诊断信息记录详情是否已打开、订单 ID、命中的标签和值、节点路径、可见文本片段与最终失败原因；不记录 Cookie、令牌或完整用户数据。

### 聊天页超时恢复

右侧上下文超时后，先中止当前页面任务，再关闭失效页面、新建并导航到查询页、等待查询控件和登录态就绪。恢复成功后继续后续行；恢复失败时保持当前“跳过该行”的安全行为，并记录恢复阶段。

## 测试与验收

先添加失败测试，至少覆盖：

1. 订单 ID 与商品信息字段在不同嵌套层级时，明确“所属品类”的值可被识别。
2. 订单 ID 不匹配、多个详情根或多个冲突品类时，S 不写入。
3. 详情弹窗初次尚未渲染、后续出现所属品类时，轮询可读取。
4. 聊天页恢复从关闭页面、新建页到就绪的成功路径，以及恢复失败时的安全降级路径。

验收以新增测试先失败后通过、相关全量测试通过、语法检查通过，以及线上部署后用真实任务日志确认 S 的来源为详情 DOM 为准。

## 非目标

- 不允许用订单列表、机会列表或模型推测替代 S。
- 不重构无关订单识别、风险分类或文件导出功能。
- 不读取或输出生产凭证与用户原始聊天数据。
